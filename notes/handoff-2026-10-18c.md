## Fixed today: invisible body with a remote set
- Symptom: 1-player System Link, fake member on slot 0 wearing spx5: archives loaded (stage request
  -> spx5), but the body was invisible (weapon showed).
- Cause: PartPath -> CarrierFor -> PartsPlayer only recognised units of class 8cc550 (parts at
  unit+0x6f70, slot at parts+0x70). In a match, the soldier is class ctor c236c0 (base c57c20),
  parts EMBEDDED at unit+0x2700 (f5c520 on this+0x9c0). So the model path fell back to our menu choice (rnd5),
  whose model wasn't loaded -> invisible.
- Fix: OwnerPlayer(owner) = the game's own f87f40 walk: for p < 16, info = game+0x28[p] (same pointers
  as the static table 0x1852080[16]), info[8]&1, x = info+0x480 (live: (x+4)&7 in {1,2}),
  x+0x40 == unit -> p. PartsPlayer uses it when the +0x6f70 check fails (after the first stage load).
  Log: `owner 0x107c0880 (parts at +0x2700) -> player 0`. User confirmed: different body in game.
- DX9: assumes the same +0x480/+0x40 offsets (untested; a wrong guess just gives -1 = old fallback).
- Diagnostics kept: g_stageSeen gating, owner lines deduped (max 32).
